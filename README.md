# easy-inno

Zero-setup Windows installer builder for Node.js applications. easy-inno bundles a fixed
**Node.js 26.13.0 LTS x64** runtime and the **Inno Setup** compiler, and turns a
production-ready Node.js project into a single Windows `Setup.exe`. The target machine needs
no Node.js, npm, Inno Setup or network access.

Windows 10/11 x64 only.

## Usage

```bash
npm install --save-dev easy-inno
npx easy-inno init
npm run package:win        # same as: npx easy-inno build
```

Output: `release/MyApp-Setup-1.0.0.exe`

All configuration lives in `package.json` (`easyInno` key). There is no second config file.

| Command | Purpose |
| --- | --- |
| `easy-inno init [--yes] [--dry-run] [--force]` | Add `package:win` script, `easyInno` settings and `.gitignore` entries. Idempotent; never overwrites existing values. |
| `easy-inno build` | Build the installer. |
| `easy-inno doctor` | Check environment, project, bundled runtime and Inno Setup. |
| `easy-inno config [--json]` | Show the effective configuration. |
| `easy-inno clean [--all]` | Remove `.easy-inno/` (and the output directory with `--all`). |
| `easy-inno version` | Print the version. |

## Requirements for your project

- A runnable production entry: `easyInno.entry`, `main`, or a single `bin`.
- `package-lock.json` (production dependencies are installed with `npm ci --omit=dev`
  using the **bundled** Node/npm, so native modules match the packaged ABI).
- Same entry for `npm run preview` and the installed app, e.g.
  `"preview": "npm run build && npm run start"`.

Root-package lifecycle scripts (`prepare`, `postinstall`, ...) are stripped from the staged
`package.json` so they do not run a second time during staging.

## Configuration

```jsonc
{
  "easyInno": {
    "entry": "dist/index.js",
    "applicationType": "console",            // or "windowed"
    "build": { "command": "npm run build", "dependencyCommand": "npm ci --omit=dev",
               "include": ["dist/**/*", "assets/**/*", "config/**/*", "package.json", "package-lock.json"],
               "exclude": ["**/*.map", "**/*.test.*", "**/*.spec.*"] },
    "runtime": { "nodeArguments": [], "applicationArguments": [], "environment": { "NODE_ENV": "production" } },
    "launcher": { "workingDirectory": "app", "forwardArguments": true, "waitForExit": true, "showConsole": true },
    "installer": { "appId": "com.example.my-app", "outputDirectory": "release",
                   "outputName": "${name}-Setup-${version}", "installMode": "perUser",
                   "icon": "assets/app.ico", "startMenuShortcut": true, "desktopShortcut": false,
                   "launchAfterInstall": true, "allowChangeInstallDirectory": true,
                   "compression": "lzma2", "solidCompression": true },
    "advanced": { "keepStaging": false, "keepIss": false, "additionalInnoDirectives": {} }
  }
}
```

Never change `installer.appId` after releasing: it is how upgrades find the existing install.
`.env*` files and `.npmrc` are never packaged unless you explicitly include a `.env*` file
(a warning is printed).

At runtime the launcher sets `EASY_INNO_INSTALL_DIR`, `EASY_INNO_APP_DIR`,
`EASY_INNO_RUNTIME_DIR`, `EASY_INNO_DATA_DIR` (`%LOCALAPPDATA%\<Name>`, kept on uninstall)
and `EASY_INNO_APP_VERSION`. `Name.exe --easy-inno-health-check` verifies the install.

Unsigned installers may trigger Windows SmartScreen; code signing is not automated in v0.1.

## Developing easy-inno

```bash
npm install
npm test                                  # build + unit tests
npm run vendor:node                       # download + SHA-256 verify Node.js 26.13.0
npm run vendor:inno -- --from "C:\Program Files\Inno Setup 7"
npm run vendor:launcher                   # compile launcher/launcher.c (MinGW gcc or MSVC)
```

The `vendor/` binaries are generated by those scripts and are included in the published npm
package (`files`), but not committed to git.
